## 自动一键成片功能 · 开发计划

### 一、功能目标概述

- **目标**：在现有 `match` 文案匹配页面中，新增「自动一键成片」模式。用户只需：
  - 选择若干已处理完成的视频素材（已完成 VLM + ASR + Embedding）。
  - 选择目标时长、候选方案数量、模式（原声/配音/自动）、类型风格。
  - 输入自由提示词（可为主题、提纲或完整文案）。
- **AI 负责**：自动完成选片、节奏规划、原声/配音策略、字幕策略、转场风格与 BGM 推荐，输出多个「完整可执行成片方案」，用户选择其中一个方案一键渲染。

### 二、整体架构思路

1. **前端层（/match 页面）**
   - 在现有文案匹配页内新增 Tab/模式：`手动文案匹配` / `自动一键成片`。
   - 自动成片模式下增加：
     - 素材选择区（复用当前“限定视频范围”组件）。
     - 自动成片配置区（目标时长、候选方案数、模式、风格、提示词）。
     - 策略对话面板（字幕策略、转场策略、BGM 策略、跨素材重排等）。
     - 候选方案列表展示区（A/B/C 方案卡片）。
     - 详细确认与执行区（查看/微调方案 + “保留/重算”开关 + 一键执行）。

2. **中台层（Auto Edit 规划服务）**
   - 新增 `auto-edit` 相关 API（例如 `POST /api/auto-edit/plan`、`POST /api/auto-edit/realize`），负责：
     - 基于选中素材的 ASR + VLM 内容和用户提示词，调用 LLM 生成结构化的「成片方案计划」。
     - 支持生成多个候选方案。
     - 支持“在旧方案基础上改动”与细粒度「保留/重算」策略。

3. **渲染层（复用 & 扩展 subtitle/export 原有管线）**
   - 复用现有：
     - `/api/subtitle/generate`（SRT 时间轴生成）。
     - `/api/subtitle/burn`（配音 + 字幕硬烧成片）。
     - `/api/subtitle/export_original`（原声成片导出）。
   - 在此基础上：
     - 增加 BGM 混音流程（整体降低 BGM 音量、Loop 补足时长）。
     - 后续逐步扩展 ffmpeg 转场（`filter_complex` + `xfade` 等），与 plan 中的 `transition` 字段对齐。

### 三、LLM 输出的结构化 Plan 设计（候选方案）

- 每个候选方案为一个 Timeline + 可选章节信息，核心结构建议如下（简要示意）：

```json
{
  "plan_id": "string",
  "title": "string",
  "summary": "string",
  "mode": "auto | voiceover | original",
  "target_duration_sec": 60,
  "estimated_duration_sec": 61.2,
  "chapters": [
    {
      "id": "intro",
      "label": "开场钩子",
      "summary": "节奏说明",
      "segments": ["seg_1", "seg_2"]
    }
  ],
  "segments": [
    {
      "id": "seg_1",
      "chapter_id": "intro",
      "order": 1,
      "clip_group": [
        { "clip_id": "xxx", "video_id": "v1", "weight": 0.8 },
        { "clip_id": "yyy", "video_id": "v2", "weight": 0.2 }
      ],
      "selected_clip_ids": ["xxx", "yyy"],
      "start_time_sec": 0.0,
      "end_time_sec": 3.2,
      "audio_mode": "original | tts | mute",
      "subtitle": {
        "strategy": "auto | asr | rewrite | none",
        "text": "本段对应的文案",
        "source": "asr | llm",
        "timing_hint": { "start": 0.0, "end": 3.2 }
      },
      "transition": {
        "type": "hard_cut | cross_dissolve | fade_in | fade_out",
        "duration_sec": 0.3
      }
    }
  ],
  "bgm": {
    "enabled": true,
    "source": "library | user | ai",
    "track_id": "bgm_001",
    "volume_db": -12.0,
    "loop": true,
    "fade_in_sec": 0.8,
    "fade_out_sec": 1.0
  },
  "constraints": {
    "max_clip_per_segment": 3,
    "match_strategy": "asr+vlm",
    "respect_user_video_order": false
  },
  "keep_flags": {
    "clips": false,
    "subtitles": false,
    "transitions": false,
    "bgm": false
  }
}
```

- 设计原则：
  - **时间线优先**：确保任意一个 Plan 都能直接映射为 `SubtitleSegmentInput[]` + 渲染参数。
  - **章节可选**：`chapters` 只做元信息，用于前端展示和后续高级能力（类似 OpenStoryline 的 Story 模型）。
  - **多方案**：返回 `plans: Plan[]`，由前端展示 A/B/C 卡片供用户选择。

### 四、后端 API 设计草案

1. `POST /api/auto-edit/plan`

- **请求体（示例）**：

```json
{
  "video_ids": ["v1", "v2"],
  "user_prompt": "做一个 60 秒的搞笑职场翻车集锦，节奏轻快，适合短视频平台。",
  "mode": "auto",
  "target_duration_sec": 60,
  "num_plans": 3,
  "allow_cross_video": true,
  "subtitle_policy": "auto",
  "transition_policy": "auto",
  "bgm_policy": "auto",
  "plan_keep_flags": {
    "clips": false,
    "subtitles": false,
    "transitions": false,
    "bgm": false
  },
  "prev_plan_id": null,
  "prev_plan": null
}
```

- **响应**：

```json
{
  "plans": [ /* 上文所述 Plan 结构数组 */ ]
}
```

- **逻辑**：
  - 查询选中 `video_ids` 的 clips：`id, video_id, start_time, end_time, duration, asr_text, vlm_description`。
  - 基于 ASR + VLM 和用户提示词，构造 LLM 上下文（可参考现有 `copy_gen.py` 的 `_build_video_context`）。
  - 使用严格的 JSON schema prompt，让 LLM 直接输出 Plan 数组。
  - 对 JSON 做 pydantic 校验，必要时重试与自动纠错。

2. `POST /api/auto-edit/realize`

- **输入**：
  - 指定一个 `plan_id` 或直接传完整 `plan`。
  - 用户在 UI 中针对 `clips/subtitles/transitions/bgm` 的保留/重算开关。
- **动作**：
  1. 根据 Plan 中的 `subtitle` 字段与策略（ASR/重写/自动）生成实际文案。
  2. 对需要配音的段落调用现有 `ttsApi` 生成 `tts_filename`。
  3. 将 Plan 转换为 `SubtitleSegmentInput[]`：
     - `copy_text` = `subtitle.text`
     - `clip_ids` = `selected_clip_ids`（或从 `clip_group` 提炼）
     - `tts_filename` 视 `audio_mode` 决定是否填入。
  4. 根据模式调用现有渲染：
     - 配音成片：`/api/subtitle/generate` + `/api/subtitle/burn`。
     - 原声成片：`/api/subtitle/export_original`。
  5. 渲染完成后执行 BGM 混音（整体降低 BGM 音量、Loop 到目标时长）。

### 五、前端交互与 UI 改造要点（MatchPage）

1. **模式切换**
   - 在 `文案匹配 · 配音 · 成片` 标题下增加 Tabs：
     - `手动匹配`：现有逻辑。
     - `自动成片`：新模式。

2. **自动成片模式布局**
   - 素材选择区：复用现有“限定视频范围”的网格选择器。
   - 自动成片配置卡片：
     - 目标时长（可选预设 + 自定义秒数）。
     - 候选方案数（2/3/5，由用户选择）。
     - 模式（自动/原声/配音）。
     - 风格输入框。
     - 提示词输入框（接受主题、大纲或完整文案）。
   - 策略对话式面板：
     - 以表单+说明的形式，引导用户选择：
       - 字幕来源策略：ASR / 重写 / 自动。
       - 转场风格策略：硬切 / 柔和淡入淡出 / 自动。
       - BGM 策略：无 / 用户自选 / AI 从库中推荐。
       - 是否允许跨素材重排。
   - 候选方案列表：
     - 每卡片显示：标题、摘要、预估时长、片段数、字幕/转场/BGM 概要。
     - 提供“查看时间线详情”和“选择此方案”按钮。
   - 详细确认与执行区：
     - 展示选中方案的 segments 表格（可读、可选少量编辑）。
     - 分别为 clips/subtitles/transitions/bgm 提供“保留/重算”开关。
     - 一键执行按钮。
     - 执行过程中支持“打断”，打断后弹出选择：是否在当前 Plan 基础上继续、保留/重算哪些部分，或完全重开。

3. **与现有组件的协同**
   - `ExportSidebar`：在自动成片模式下可简化为“结果导出面板”，或直接由自动成片流程产出后统一调用现有导出逻辑。
   - `SubtitlePanel`：在用户选择了“添加字幕”且模式为配音/原声时，用于预览字幕样式与位置。

### 六、渐进式落地路线图

**Phase 1：Plan 原型（后端为主）**
- 新增 `/api/auto-edit/plan` 接口，能基于选中视频 + 用户提示词返回结构化 Plan 数组。
- 暂不实现转场 & BGM 的实际渲染逻辑，只在 Plan 中先有字段占位。
- 前端新增简单的“自动成片” Tab，只完成：
  - 调用 plan 接口。
  - 展示候选方案列表（标题、摘要、预估时长、segments 数量）。

**Phase 2：与现有渲染管线打通**
- 实现 `/api/auto-edit/realize`：
  - 将 Plan 转换为 `SubtitleSegmentInput[]`。
  - 复用 `subtitle.generate` / `subtitle.burn` / `subtitle.export_original` 实际导出 MP4。
  - 暂时不做复杂转场，仅硬切 + 字幕 + 原声/配音。
- 前端在自动成片模式下，支持：
  - 从某个 Plan 一键生成最终成片（下载链接或在 UI 里预览）。

**Phase 3：BGM 支持**
- 设计 BGM 素材库与元数据（风格、情绪、节奏等）。
- 增加：
  - Plan 中 BGM 字段的实际选曲逻辑（根据用户风格/提示词/模式）。
  - ffmpeg 混音流程：整体降低 BGM 音量、Loop 补足长度、支持简易淡入淡出。

**Phase 4：转场与高级编辑**
- 在 `burn.py` 中为「最终合并」阶段增加 `filter_complex` 流程：
  - 支持 `xfade` 等基本交叉溶解 / 淡入淡出转场。
  - 尝试音频与视频同步转场（淡入淡出）。
- Plan 中 `transition` 字段真正驱动渲染。
- 根据实际体验，逐步丰富：
  - 更多转场类型。
  - 细粒度节奏控制与镜头长度分布策略。

**Phase 5：对话式迭代 & 打断/重算**
- 在 Plan 基础能力稳定后，完善：
  - 执行中打断 + 改策略的交互。
  - `keep_flags` 的细粒度控制（clips/subtitles/transitions/bgm）。
  - 旧 Plan 的复用（基于 `prev_plan_id` 或直接传入 `prev_plan`）。

     - `mode=original`：走 `subtitle.export_original`。

4. 前端候选方案卡片已支持「一键成片」（Phase 2）
   - 已接入 `autoEditApi.realize`。
   - 成功后可直接触发下载生成的 MP4 文件。

5. `POST /api/auto-edit/realize` 增强（Phase 2 收尾 + 增强）
   - 已新增 `clip_id` 有效性预检：在 realize 前统一检查 Plan 中引用的 `clip_id` 是否存在于 `clips` 表。
   - 当 Plan 中存在无效 `clip_id` 时，错误信息会包含 `invalid_clip_ids` 列表，便于前端或用户快速定位问题。
   - 当 `selected_clip_ids` 无效或缺失时，已支持按 `segment.start_time_sec/end_time_sec` 在候选素材中自动回退到最接近的片段。

6. `POST /api/auto-edit/realize` 已接入 BGM 后处理混音（Phase 3 最小可用版）
   - 当 `plan.bgm.enabled=true` 且可解析到本地 `track_id` 时，在成片导出后自动执行 ffmpeg 二次混音。
   - 已支持参数：`volume_db`（音量）、`loop`（循环补齐到成片时长）、`fade_in_sec`、`fade_out_sec`。
   - 混音失败会自动回退原成片（不中断 realize 主流程）。

7. BGM 自动选曲兜底（Phase 3 增强）
   - 当 `bgm.source in (library, ai)` 且 `track_id` 缺失/无效时，realize 会自动扫描 `backend/storage/bgm` 本地音乐库。
   - 基于 Plan 的 `title/summary/segments.subtitle.text` 做轻量关键词打分，优先选择最匹配的本地音轨。
   - 若没有明显关键词命中，则回退到库内第一首可用音轨，保证流程可继续。

8. BGM 元数据清单（manifest）已接入（Phase 3 增强）
   - 新增 `backend/storage/bgm/bgm_manifest.json` 示例模板，支持为曲目维护 `mood/bpm/tags` 等元信息。
   - 自动选曲时优先读取 manifest 做打分（mood 强匹配 + tags/title 关键词 + BPM 接近度），再回退到纯文件名关键词匹配。

9. BGM 管理页面 & 后端管理 API 已上线（Phase 3 增强）
   - 后端新增 `backend/app/api/bgm.py`，提供 `/api/bgm/tracks`（列出）、`/api/bgm/upload`（上传）、`/api/bgm/tracks/{id}`（更新/删除）接口，负责管理 `storage/bgm` 目录与 `bgm_manifest.json` 清单。
   - 前端在 `/settings` 页面新增「BGM 音乐库」区块（`BgmSection`），支持通过 UI 完成 BGM 上传、试听、情绪 `mood` / BPM / 标签 `tags` 编辑与删除，无需再手动维护 JSON。
   - BGM 管理与自动选曲逻辑解耦：配置层由设置页负责，自动成片时只消费结构化的曲目元数据。

#### 7.2 已定位并修复的问题

1. Plan 中出现不存在的 `clip_id`（如 `clip_001`）导致 realize 报错
   - 现象：`detail: "片段不存在: clip_001"`。
   - 原因：LLM 生成了伪造 clip_id，未严格复用数据库真实 `clips.id`。
   - 修复：
     - `_build_video_context` 已改为显式输出 `clip_id`（格式：`[clip_id=xxxx]`）。
     - `auto_edit` 的 system prompt 已增加硬约束：`clip_group[*].clip_id` 和 `selected_clip_ids` 必须原样复用素材上下文中给出的真实 clip_id。

#### 7.3 当前限制（待后续迭代）

1. 目前 realize 仍基于已有 `clips` 物理片段拼接，不是按“原视频绝对时间”实时重切。
2. `keep_flags` / `prev_plan_id` / `prev_plan` 仅保留字段，尚未实现细粒度保留重算逻辑。
3. BGM 已支持 manifest 元数据选曲 + 文件名关键词兜底，但仍缺少“基于用户偏好/历史反馈的个性化选曲”与“LLM 二次重排”能力。
4. 转场字段 `transition` 尚未驱动真实渲染（Phase 4 待做）。
5. 当前自动回退选片为“时间窗最接近”策略（重叠优先、中心点距离次之），尚未结合语义（ASR/VLM）做二次排序。

#### 7.4 下一步建议（与当前代码对齐）

1. Phase 3（继续）：在 manifest 基础上增加评分可配置化（权重/关键词词典）与候选 Top-K 输出（便于前端展示可选曲目）。
2. Phase 4：在 `burn.py` 引入 `filter_complex + xfade`，让 `transition` 真正生效。
3. Phase 5：实现 `keep_flags` + `prev_plan_id/prev_plan` 的增量重算链路（仅重算字幕、仅重算镜头等）。
4. 自动回退策略升级：在“时间窗最接近”基础上叠加 ASR/VLM 语义相似度打分。
5. 前端自动成片 UI 增强：在 `/match` 的自动成片模式中接入 BGM 曲目选择器，允许在「AI 自动推荐」基础上手动锁定/切换 BGM，而不是只能由系统隐式决策。
